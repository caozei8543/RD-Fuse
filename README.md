### Submission note

The two PDFs are the unaltered author-supplied final documents. The LaTeX source was **reconstructed from the PDF**, rather than exported from the original author Word file; a regenerated LaTeX PDF may differ in layout. For a journal requiring matching source and PDF, use the actual author-side source if available. Do not treat the reconstruction as an exact original Word-to-LaTeX conversion.

The included Python implementation was assembled from the manuscript description. It supports inspecting, testing and developing the methods, but has **not been matched to the original experiment scripts or independently demonstrated to reproduce the paper's benchmark and Jetson metrics**. The manuscript reports the authors' experimental findings; the packaged code's tests do not independently validate those findings. Synthetic inputs and example latency costs are test fixtures, not experimental measurements.

## Quick start

From the extracted directory (Python 3.10+):

```bash
python -m pip install -e '.[test]'
python -m pytest -q
bash scripts/run_smoke.sh
```

Optional PVTv2 adapter requires `timm`:

```bash
python -m pip install -e '.[pvt,test]'
```

To use real paired data, prepare a JSON manifest following `docs/DATA_PROTOCOL.md`. The smoke command trains for one step per stage on synthetic data and saves outputs in `artifacts/` (not included in the archive).

```bash
python -m scripts.validate_latency_profile configs/demo_profile.json
python -m scripts.audit_paper_source --out ''
```

The first command checks *format* of example costs; it does not measure device latency. `scripts/profile_pytorch.py` measures PyTorch timing, not TensorRT latency. The second command checks submitted PDF checksums and reconstruction structure.

## Model-to-paper implementation notes

- **Semantic probe:** global/local cross-modal descriptors and reliability estimates (`rd_fuse/probe.py`).
- **Utility estimates:** signed detection-loss gains from forced-route / one-window interventions (`rd_fuse/training.py`).
- **Routing:** feasible top-k path/window allocation using configured cost profiles (`rd_fuse/routing.py`).
- **Regret stage:** actual sampled multiwindow detector losses in the decision objective, not merely an additive regional-loss assumption.
- **Conditional execution:** deep branches and window attention not selected by a route are skipped (`rd_fuse/model.py`).
- **Evaluations:** the bundled compact AP and detection target implementation are engineering components and are not represented as the original published evaluation harness. See `docs/IMPLEMENTATION_NOTES.md`.

The manuscript reports M3FD 90.1%/62.7% and LLVIP 94.8%/62.2% mAP50/mAP50:95; on Jetson Orin NX it reports 19.8 average GFLOPs and 17.6 ms mean latency. ## Supplementary configuration and reference workflow

`configs/m3fd.yaml` and `configs/llvip.yaml` select the six-class and one-class models and respective 70/35/55 and 50/25/45 stage lengths. `docs/AUTHOR_CONFIRMED_SETTINGS.md` records the author-confirmed supplementary settings, including the routing cost table and seed summaries, with provenance. These summary records are not raw experiment logs.

The updated reference trainer supports stage-local cosine LR, five initial warmup epochs, periodic in-memory counterfactual target refresh (frozen detector and fixed per-sample flip within each refresh block), random feasible budget ratios, linear regret temperature annealing and gradient accumulation. Physical batch and restart policy are implementation choices. No strict latency guarantee is asserted. Example invocation with an actual measured profile and dataset manifest:

```bash
python -m pip install -e '.[pvt,test,coco]'
python -m scripts.train_all --dataset m3fd --manifest /path/train.json --profile /path/measured_profile.json --seed 42 --device cuda
python -m scripts.evaluate --checkpoint artifacts/runs/m3fd/42/regret.pt --manifest /path/test.json --profile /path/measured_profile.json --metric coco --device cuda
```

Repeat for all three seeds and the LLVIP configuration. Evaluation exports per-image predictions, route counts, selected windows, predicted utilities and estimated costs. The optional `pycocotools` adapter calculates all-area bbox AP on letterboxed manifest coordinates, with standard COCO maxDets=100 for AP; it does not recover crowd/ignore annotations absent from the manifest. Do not equate it to the original experiment protocol without checking the original evaluator. `compact` remains the dependency-free default for software smoke tests.

`configs/author_confirmed_profile.json` may be passed explicitly to exercise the router at the confirmed budgets, but no raw device traces accompany it. The existing `configs/demo_profile.json` remains reserved for synthetic software testing. Evaluation outputs are generated only by running a checkpoint on a manifest; no fabricated model weights, per-image predictions, hardware traces or training logs are shipped.
